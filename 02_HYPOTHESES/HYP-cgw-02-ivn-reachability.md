# HYP-cgw-02 — 10.224.139.0/24（BCM/BMS/VCU）能否从本 VPN 侧到达

- **日期**：2026-11-14 09:3x–09:5x
- **负责人**：ecu-bridge
- **所属**：C03 核心 KPI「找到进 10.224.139.0/24 的路」；C04/C05/C06/C10 的前置
- **状态**：**已证伪（VPN 侧无路由，不可达）**；唯一入口是 CGW，而 CGW 无转发面

## 判据（先写后跑）

「不可达」必须用**正对照**证明，不能只写「连不上」：

1. **正对照 1**：同一 VPN 内已知存活主机（`10.230.164.4`、`10.229.221.2`）
   的 `tracert` 应在第 2 跳即到达目标本身。
2. **正对照 2**：对已知存活主机打**关闭端口**，若回 RST ⇒ 本机具备「主机存活」判别能力；
   若该主机 DROP ⇒ 说明"关闭端口超时"不能反证主机不存在（须记入局限）。
3. **待测**：`tracert 10.224.139.x` 若在第 1 跳（VPN 网关）之后全静默，
   且**同 /12 内另一个未部署网段**（如 `10.224.1.1`）表现一致，
   则说明「VPN 对端只真正路由了 10.229.221.0/24 与 10.230.164.0/24，其余 /12 被黑洞」。
4. 辅助：ICMP 普查 + UDP/TCP 探测，排除「主机在但屏蔽 ICMP」。

## 实验结果

| # | 实验 | 结果 |
|---|---|---|
| 1 | `route print -4` | 仅一条 `10.224.0.0/12 → 10.252.3.1`, 出接口 TAP `10.252.3.20`, metric 257。ovpn 内亦只有 `route 10.224.0.0 255.240.0.0` |
| 2 | `tracert 10.230.164.4` / `.2`（正对照） | **2 跳到达**：hop1 `10.252.3.1` (26–29ms)，hop2 即目标本身 ⇒ VPN 对端确实路由 10.230.164.0/24 |
| 3 | `tracert 10.224.139.5` / `.1` | hop1 之后**连续超时**；`.1` 有一次连 hop1 都不回（抖动） |
| 4 | `tracert 10.224.1.1`（同 /12 未部署网段） | hop1 回 25ms，hop2+ **全静默** ⇒ 与 10.224.139.x 表现一致 ⇒ **不是针对 139 段特判，是整段没路由** |
| 5 | `ping` 对照 | `10.230.164.4` 3/3 回（28–32ms）；`10.224.139.5/.6/.7` 0/3、0/2、0/2；`10.252.3.1` 0/3（TAP 网关不回 echo，但回 TTL-exceeded） |
| 6 | RST 存活判别基线 | `10.229.221.2:9999` → **RST 2.6s**（存活）；`10.230.164.2:9999` → **RST 2.2s**（存活）；`10.230.164.4:9999` → **超时 3.0s**（但该机存活，8080 开）⇒ **本舰队里存在"存活但 DROP 关闭端口"的主机，故 139 段超时≠死** |
| 7 | ICMP 普查 `10.224.139.0/24` | **0/254 存活** |
| 8 | ICMP 普查 `10.229.221.0/24` | 1/254（仅 `.2`）⇒ 无可作跳板的其他主机 |
| 9 | ICMP 普查 `10.230.164.0/24` | 2/254（`.2`、`.3`；`.4` 本轮未回 ping，说明该段 ICMP 本身有抖动/限速） |
| 10 | 端口普查 `10.229.221.0/24` + `10.230.164.0/24`（22/80/443/8080/8443/13400/13401/1883/5000/8000） | 仅 `.2:8080`、`.2:13400`、`.2:13401`、`164.2:8080`、`164.3:8080`、`164.3:8443`、`164.4:8080/13400/13401` |
| 11 | UDP 探测网关（53/67/68/123/137/161/162/500/514/623/1900/3702/4500/5000/5353/5355/5683/13400/13401/20000/33333/47808） | **全部无回应**（含标准 DoIP UDP 13400 车辆识别） |

## 结论

1. **VPN 侧对 10.224.139.0/24 没有任何可用路由**。判据不是"连不上"，而是：
   同一 /12 内**已知存活**主机在第 2 跳即到达（正对照成立），
   而 `10.224.139.x` 与**另一个根本没部署的 `10.224.1.1`** 表现完全一致（hop1 之后全静默）。
   ⇒ VPN 对端实际只路由 `10.229.221.0/24` 与 `10.230.164.0/24`，其余 /12 黑洞。
2. **没有双宿跳板机**：两个可达 /24 内除已知 4 个服务地址外无任何存活主机。
3. ⇒ 若 BCM/BMS/VCU 存在，只能**经 CGW 转发**。而 CGW 侧：
   - DoIP 13400 只有一个逻辑地址 `0x1000`，只实现 `0x22`，DID 空间 65536 全扫仅 `F190`/`F1A0` 有值；
   - 8080 无 API 面（HYP-cgw-01）；
   - 13401 连上即 FIN（HYP-cgw-03）。
   ⇒ **CGW 不提供任何到 10.224.139.0/24 的转发面**。

## 局限（必须随结论一起引用）

- 本机**非管理员**，无法 `route add`，也无法发 raw ICMP ⇒ 不能自造路径/自造探测包。
- Windows 上"关闭端口"既可能 RST 也可能被 DROP（本舰队两种都有），
  因此**单看端口超时不能判定主机不存在**；本结论依靠的是 traceroute 正对照 + 网段一致性，不是端口超时。

## 对队友的影响

- `portscan.py --self-test` 在本机会把"关闭端口"判成 `filtered`（实测 FAIL），
  ⇒ 任何人用它的 `filtered` 计数论证"目标被防火墙挡"都是无效论证，必须改用 traceroute 正对照。
