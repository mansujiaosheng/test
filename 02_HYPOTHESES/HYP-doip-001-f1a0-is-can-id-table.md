# HYP-doip-001 — 网关把 TA=0x07E0 等地址路由到 CAN，只是 ECU 不回

**提出** 2026-11-14 09:10（基于 brief：TA=0x07E0/0x0010 收 `7F 22 31`）
**状态** 已证伪（2026-11-14 09:35）
**证据** `03_EVIDENCE/cgw/doip_ta_matrix.txt`、`doip_sweep_ta_all.jsonl`

## 假设
`F1A0` 返回 `07E0 07E8 07E1 07E9`，看起来是 ECU 地址表。若网关把它们当路由目标，那么
发往 TA=0x07E0 的请求应该被转发到 CAN 总线，只是总线后面没 ECU 应答（超时或 DoIP NACK）。

## 证伪方法
对 TA=0x07E0 发 `3E00` / `22F190` / `1001`，观察响应来源与 NRC：

```
TA=0x07E0 3E00   -> 7F3E31  380ms
TA=0x07E0 22F190 -> 7F2231  380ms
TA=0x07E0 1001   -> 7F1011? 见矩阵（实为 7F1031）
```

响应 **SA=0x1000**（网关自己），NRC=0x31 requestOutOfRange。若请求真的被转发到 CAN，
响应来源应该是 0x07E8 那侧的 ECU 逻辑地址，或至少是 DoIP 0x8003 NACK（目标不可达）。
网关是在**本地**直接拒绝，根本没有转发。

## 结论
`F1A0` 的内容不是 DoIP 路由表。结合 `0x7E0/0x7E8` 是 ISO 15765-4 里**动力总成诊断请求/响应**
的标准 11-bit CAN ID 对（0x7E0 请求、0x7E8 响应；0x7E1/0x7E9 为第二组），最合理的解释是：
**`F1A0` 是 13401 CAN FD 桥要暴露的 CAN 诊断 ID 清单，不是 13400 的逻辑地址表。**

## 移交
13400 侧不存在通往这些 CAN ID 的通道。要碰 0x7E0/0x7E8 只能走 13401（cgw 组负责）。
