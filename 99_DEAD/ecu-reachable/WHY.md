## 结论

`10.224.139.5/.6/.7` 在 IP 层 **filtered**：SYN 发出后**零回包**（既无 `syn-ack` 也无 `rst`）。
不是"服务没起来"（那会 `conn-refused`），也不是"有状态防火墙拦 SYN"（那 ACK 扫描会回 RST）。
是**路径上直接丢包**：该子网对 VPN 客户端不存在。

## 证据

`TTL=63` ⇒ 到已知目标只经过 **1 个路由器**。链路本身是通的。

### 2. tracert（`tracert_targets.txt`）

### 3. TCP 扫描（`syn_5_6_7.nmap` / `.gnmap` / `.xml`）

```
nmap -Pn -n -sT -p 22,80,443,8080,8443,13400,13401 --reason 10.224.139.5 10.224.139.6 10.224.139.7
```

21 个 (主机,端口) 组合，**全部 `filtered`，reason 全部 `no-response`**：

| 主机 | 22 | 80 | 443 | 8080 | 8443 | 13400 | 13401 |
|---|---|---|---|---|---|---|---|
| .5 | filtered | filtered | filtered | filtered | filtered | filtered | filtered |
| .6 | filtered | filtered | filtered | filtered | filtered | filtered | filtered |
| .7 | filtered | filtered | filtered | filtered | filtered | filtered | filtered |

`no-response` 是关键：**一个包都没回来**。
- 若主机在但端口关着 ⇒ `conn-refused`（RST）
- 若主机在但有防火墙拦 SYN ⇒ `filtered`，但 ACK 扫描应见 RST
- 若**路径丢包** ⇒ `no-response`（就是这里）

### 4. 关于 `-sS` / `-sA`（`ack_scan_limitation.txt`）

**本机非管理员，nmap 拿不到 Npcap 原始套接字，`-sS` 与 `-sA` 静默失败（输出为空、退出码 0）。**
这不是"扫了没结果"，是"根本没扫成"。踩坑记录：

```
D:/TOOL/nmap/nmap.exe -Pn -n -sS -p 8080 --reason 10.230.164.4   → 只有 "Starting Nmap"，无报告，exit 0
D:/TOOL/nmap/nmap.exe -Pn -n -sT -p 8080 --reason 10.230.164.4   → 正常出报告
```

⇒ **本机只能用 `-sT`（connect 扫描）**。`-sT` 的 `no-response` 与 `-sS` 的 `filtered` 语义等价：
`connect()` 超时 = 没收到 SYN-ACK 也没收到 RST。已用 TTL=63 的已知可达主机验证 `-sT` 工作正常。

**因此「ACK 扫描回 RST 但 SYN 不回」这个判据本机做不了**，只能改用
`ping + tracert + -sT no-response` 三条独立证据交叉，结论一致。

- **`-sA` ACK 扫描**：见 §4，无原始套接字。
