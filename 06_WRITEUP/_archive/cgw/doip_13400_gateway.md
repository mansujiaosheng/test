## 1. 方法论：先建立判据，再枚举

这台的 NRC 是**分两层**的，这是整条路最重要的发现，直接决定枚举怎么判：

```
请求 → TA=0x1000（网关自己）
        ├─ 服务不存在        → 7F <sid> 11  serviceNotSupported
        └─ 服务存在、DID 不在表内 → 7F 22 31   requestOutOfRange
请求 → TA=其它（网关不认识）
        └─ 一律本地拒绝       → 7F <sid> 31  （from=0x1000）

未做 routing activation → 7F <sid> 22  conditionsNotCorrect（不是 DoIP NACK！）
```

所以**不能只看"有没有响应"**：网关对不认识的 TA 也会回，只是 NRC=0x31。
正确判据是 `from=0x1000 且 NRC==0x31` → 不认识；偏离 0x31 → 该地址存在。

同理，服务枚举不能看"有没有响应"，要看 NRC 是否等于 0x11。

## 2. 三条枚举的全部结果

### 2.1 逻辑地址：898 个里只有 1 个活

范围覆盖任务书要求的全部区段：`0x0001-0x00FF`(255)、`0x0700-0x07FF`(256)、`0x0E00`、
`0x0E80-0x0EFF`(128)、`0x1000`、`0x1001-0x10FF`(255)、`0x18DA00F1`/`0x18DB33F1`。

```
897 × 7F3E31  (BASELINE: 网关不认识这个目标)
  1 × 7F3E11  (TA=0x1000: 认识目标，但 TesterPresent 未实现)
```

非基线行全部用 4.0s 超时复测 2 轮，无一改判。
原始数据 `03_EVIDENCE/cgw/doip_ta_matrix.txt`（898 行，含每行延迟）。

> **协议细节**：`0x18DA00F1`、`0x18DB33F1` 是 29-bit CAN ID，而 DoIP 逻辑地址字段只有 16 位，
> 发出去必然被截断成 `0x00F1`/`0x33F1`。这两个值不属于 DoIP 地址空间，列出来只为证明截断后同样 0x31。

### 2.2 UDS 服务：256 个里只有 0x22

每个 SID 试最多 6 种 payload 形状（空 / `00` / `01` / `0000` / `0100` / `010000`），
因为这台对长度极其挑剔（见 §3.2）。1533/1534 条有响应：

```
SID 0x22  → 7F2211 / 7F2231   ← 唯一存在
其余 255  → 7F <sid> 11       ← serviceNotSupported
```

`10/11/14/19/27/28/2E/2F/31/34/35/36/37/38/3E/23/24/29/2A/2C/3D/83-87/BA` 逐个确认。

**没有任何写类服务可执行** —— `2E`、`31`、`34/36/37` 连分发都进不去（0x11），
所以本次"只读纪律"在技术上由目标本身保证，不存在误写风险。

### 2.3 DID：65536 个里只有 2 个

| DID | 响应 | 内容 |
|---|---|---|
| `F190` | `62 F1 90 43 56 36 46 46 35 32 46 45 45 39 45 44 44 44 38 36` | VIN `CV6FF52FEE9EDDD86` |
| `F1A0` | `62 F1 A0 07 E0 07 E8 07 E1 07 E9` | 4 个 CAN 诊断 ID |
| 其余 65534 | `7F 22 31` | 不存在 |

> 全扫由 cgw 组完成（`0424_didscan_0000_ffff.jsonl`）。本组负责**复核**其中 38 个
> 当时"无响应"的异常 DID（`0x3CE0-0x3CE2`、`0x8DA0-0x8DA9`、`0xA7E0-0xA7F7`、`0xF1A8`）：
> 4.0s 超时 × 3 轮，**38/38 全部稳定 `7F 22 31`**。其中 `0xA7EA`/`0xA7F2`/`0xA7F3` 各命中一次
> 4.0s 超时 —— 是长尾延迟，不是代码路径差异。
> 特别关注 `0xF1A8`（紧挨 `F1A0`，最有价值的位置）：干净返回 `7F 22 31`。

## 3. 三条被证伪的假设（不写清就容易被人重做）

### 3.1 "`F1A0` 是 ECU 地址表，后面有 ECU 只是不应答"

`F1A0` = `07E0 07E8 07E1 07E9`。把它们当 TA 发：

```
TA=0x07E0 3E00   -> 7F3E31 (from 0x1000)
TA=0x07E0 22F190 -> 7F2231 (from 0x1000)
```

响应来自**网关自己**、NRC=0x31。若真的转发到 CAN，响应来源应是 0x7E8 那侧的地址，
或至少是 DoIP 0x8003 NACK（目标不可达）。**网关是本地拒绝，根本没转发。**

`0x7E0/0x7E8` 是 ISO 15765-4 里动力总成诊断请求/响应的标准 11-bit CAN ID
（`0x7E1/0x7E9` 为第二组）。所以 `F1A0` 是**给 13401 CAN FD 桥的目标清单**，
不是 13400 的路由表。→ 要打这四个 ID 只能走 13401。

### 3.2 "0x000A/0x000B/0x0022..0x0033 无响应 = 隐藏地址段"

用 5.0s 超时 + 换 probe 重测，它们与 `0x0001/0x0009/0x0021/0x0034` 表现**完全一致**（`7F3E31`，~380ms）。

真实成因：网关偶发慢应答。150 连发实测 p95=799ms、max=1014ms，另一轮 4s 超时重测里
有三条命中 4.0s；而 gap=0 连发 150 次 **150/150 全回**，无速率限制。
**0.8s 的 timeout 正好切在长尾里**，慢的那几次被记成 TIMEOUT。

**纪律**：任何 TIMEOUT 必须 ≥3s timeout 复测 ≥3 次才可采信。
（`doip_client.py sweep-ta` 已内建 `--retries 2 --retry-timeout 4.0`。）

### 3.3 "SecurityAccess 可逆 → 解锁更多 DID"

`27 01` → `7F 27 11` = **serviceNotSupported**（不是 0x12、也不是 0x7F）。
0x11 意味着 SID 0x27 **根本没被分发**，不存在"先开扩展会话才有 SecurityAccess"。
而 `10 01/02/03` 也是 `7F 10 11` —— 会话控制本身不存在，提升会话这条链第一步就断了。
**本组未做任何 SecurityAccess 穷举**（预算省下）。

## 4. 真阳性：routing activation 不绑定 SA（中低危）

### 4.1 规范要求
ISO 13400-2：诊断报文的 SA 必须已在该 socket 完成 routing activation，否则实体应回
DoIP `0x8003` negative acknowledge，code `0x02`（invalid source address）。
同一 SA 已在别的 socket 激活时，应回 `0x06` 响应码 `0x03`。

### 4.2 实测

**（a）激活一次之后，任意 SA 都放行**
```
socket 激活 SA=0x0E00 -> code 0x10 routing successfully activated
SA=0x0E00 -> 62F190...3836
SA=0x0E80 -> 62F190...3836     ← 未激活的 SA
SA=0x0777 -> 62F190...3836     ← 未激活的 SA
```

**（b）SA 完全由客户端声明，回包照抄**
```
00 00 10 00 22 F1 90 -> from=0x1000 to=0x0000  62F190...
10 00 10 00 22 F1 90 -> from=0x1000 to=0x1000  62F190...   ← 冒充网关自身
07 E0 10 00 22 F1 90 -> from=0x1000 to=0x07E0  62F190...   ← CAN ID 当 SA
```

**（c）同一 SA 可在多个 socket 同时激活**
```
socket A activate SA=0x0E00 -> 0x10
socket B activate SA=0x0E00 -> 0x10    ← 应为 0x03
socket B 再换 SA=0x0E80     -> 0x10    ← 已激活的 socket 可随意换 SA 重激活
```

**（d）激活类型不校验**
`act type` = 0x00/0x01/0x02/0x03/0x04/0xE0(OEM)/0xFF(保留) **全部 0x10 成功**，
OEM 附加数据（`01020304`、`DEADBEEF`）被完全忽略。规范要求不支持的激活类型回 `0x06`。

**（e）未激活时用错了协议层**
```
(不做 0x0005，直接发 0x8001)
22F190 -> 7F 22 22     (NRC 0x22 conditionsNotCorrect, from 0x1000 to 0x0E00)
10 01  -> 7F 10 22
```
"未激活"被当成 ECU 条件不满足，而不是 DoIP 路由错误。

### 4.3 定级与影响边界（不夸大）
**中低危：缺失 source-address 绑定校验。** 在多实体车端拓扑里，这足以绕过
"哪个 tester 能访问哪个 ECU"的准入设计（任何 tester 都能声称自己是任意 SA，包括网关自身）。

**但本靶场不成立越权**：13400 后面只有一个只读 UDS 实现，未观察到越权读取。
报告里**不要写成"可越权访问任意 ECU"**——那是本靶场不支持的断言。

## 5. 其它协议偏离（同一条报告里可并列）

| # | 偏离 | 规范要求 | 实测 |
|---|---|---|---|
| 1 | 协议版本不互补 | 回 NACK `0x00` | **静默丢弃**（ver=0x01/0x03/0x04、inv 不互补全部无响应） |
| 2 | 识别响应长度 | 32 字节（VIN17+LA2+EID6+GID6+FA1） | **33 字节**，多 1 个 `00` |
| 3 | `0x0002`/`0x0003` 识别 | 应支持按 EID / 按 VIN 识别 | 一律 NACK `0x01`（含正确长度） |
| 4 | `0x0001` 带多余数据 | 应 NACK | **接受**（带 6 字节垃圾数据仍正常响应） |
| 5 | 长度字段与实际不符 | — | 按声明长度**阻塞读**（`declared=0xFFFF` 会挂住），非内存破坏面 |
| 6 | alive check `0x0007` / entity status `0x4001` / power mode `0x4004` | 应实现 | 全部 NACK `0x01` |

> 关于偏离 2 的一个追问已排除：那多出的第 33 字节**不是**堆内存泄漏。
> 60/60 次采样恒为 `0x00`，且在灌入畸形/异常流量后仍然稳定，是固定结构体内容。
> 证据 `03_EVIDENCE/cgw/doip_ident_offbyone_probe.txt`。

## 6. 为什么这里没有 flag

可读数据只有三样，全是结构性固定值：

- **VIN** `CV6FF52FEE9EDDD86`（与 TSP 的 demo VIN `CV6000000DEMO0001` 不同，是真实车 VIN）
- **4 个 CAN ID** `07E0 07E8 07E1 07E9`
- **EID** `060000001000` / **GID** `000000000000`

按赛事宽松正则 `[A-Za-z0-9_]{2,20}\{[ -~]{1,120}\}` 扫全部 13400 证据：零命中。

**13400 的角色是"路标"**：告诉你 13401 后面挂着 `0x7E0/0x7E8/0x7E1/0x7E9` 四组诊断 ID。
T03 的得分点应在那四个 CAN ID（13401）或 8080 上。
