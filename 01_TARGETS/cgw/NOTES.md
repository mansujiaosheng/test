# CGW (10.229.221.2 / 10.230.164.4) 已确证事实

> 采集时间 2026-11-14 09:20–09:40 (Asia/Shanghai)。所有结论为**严格锁步**单连接实测（并发/流水线探测会产生错位假象，见文末"假象"节）。

## 2. DoIP 13400 上的 UDS 服务面（关键结论）

**只实现 0x22 ReadDataByIdentifier。** 其余服务一律 `7F <svc> 11`（serviceNotSupported）。

逐个服务实测（正确长度载荷）：
```
1000/1001/1002/1003 → 7F1011     2701/2702 → 7F2711
1101                → 7F1111     2EF190..  → 7F2E11
2800/2801/2803      → 7F2811     2FF1900301→ 7F2F11
3101/3102/3103 × RID → 7F3111    3400/3600/3700 → 7F3411/7F3611/7F3711
3E00/3E80           → 7F3E11     8510/8501/8502 → 7F8511
1900FF/1901FF/1902FF → 7F1911
```

**DID 表（严格锁步扫 0xF100–0xF1FF，256 条，8.6s）：只有 2 个正解**

| DID | 响应 | 含义 |
|---|---|---|
| `0xF190` | `62 F190 4356364646353246454539454444443836` | VIN `CV6FF52FEE9EDDD86` |
| `0xF1A0` | `62 F1A0 07E0 07E8 07E1 07E9` | 下游 ECU 的 CAN 请求/响应 ID 对：`0x7E0↔0x7E8`（ECU A）、`0x7E1↔0x7E9`（ECU B） |
| 其余 254 个 | `7F 22 31` requestOutOfRange | |

**目标逻辑地址（TA）空间扫描**（0x0000–0x00FF / 0x0E00–0x0EFF / 0x1000–0x10FF，共 768 个 TA × `22F190`）：
- 只有 **TA=0x1000** 得到正解；其余全部由 0x1000 回 `7F2231`。
- 即：网关**不把 DoIP 诊断路由到任何下游 ECU**，它只回答自己。

## 3. CAN FD 桥 13401

- TCP connect 成功，**服务端不读请求字节就立即 FIN**（实测 0.01–0.05s，recv 返回 b''）。
- 不是 TLS：`openssl s_client` 报 `unexpected eof while reading`，`handshake has read 0 bytes`。
- 无论发送空、`00×8`、`55×16`、socketCAN canfd_frame(72B)、ASCII 均同结果。
- 先做 13400 ident+RA（含各种 activation type / OEM 字段）后再连，**仍然立即 FIN**。
- 读 `22F190` / `22F1A0` 之后立刻连，仍然立即 FIN。
- 两个网关实例（10.229.221.2 与 10.230.164.4）行为一致。

→ **13401 处于关闭态，且 13400 的 DoIP/UDS 面没有任何"开桥"能力。**

## 4. 假象与陷阱（重要，避免重走）

**并发/流水线探测会污染结论。** 网关对同一账号（或全局）似乎只有单会话状态；两个连接同时发请求时，响应会错位，表现为：
- 全量 65536 DID 扫描（87s，流水线）报告只有 `F1AB`/`F1BB` 两个"正解"，且响应体里的 DID 是 `F190`/`F1A0` —— 纯属错位；
- 高速 TA 扫描（763 个 TA）报告 `TA=0x1004` 正解 —— 同样是错位。
- 严格锁步复测后，这些全部消失。

**判据**：任何 DID/TA 命中，必须在"单连接 + 单请求 + 等待响应"下复现 ≥2 次才算数。
