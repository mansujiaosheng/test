## 3. 逻辑地址枚举结果——网关后面**没有第二个 DoIP 实体**

`sweep-ta` 共探测 **898 个 TA**，probe `3E00`，SA=0x0E00，超时 2.0s，非基线行各复测 2 轮（4.0s）：

| 范围 | 数量 |
|---|---|
| 0x0001–0x00FF | 255 |
| 0x0700–0x07FF | 256 |
| 0x0E00 | 1 |
| 0x0E80–0x0EFF | 128 |
| 0x1000 | 1 |
| 0x1001–0x10FF | 255 |
| 0x18DA00F1 / 0x18DB33F1 | 2 |

**结果：897 个 `7F 3E 31`（BASELINE），1 个 INTERESTING = 0x1000（`7F 3E 11`）。**
即网关只认自己，对其他任何地址都是本地 NACK `requestOutOfRange`。

判据（本组建立，比"看有没有响应"可靠得多）：

```
响应 SA=0x1000 且 NRC=0x31  -> 网关不认识这个目标（baseline）
响应 TA=0x1000 且 NRC=0x11  -> 网关认识目标，但服务未实现
其它                        -> 值得复测
```

> 注意：`0x18DA00F1` / `0x18DB33F1` 是 29-bit CAN ID，DoIP 逻辑地址只有 16 位，
> 发出去会被截断成 `0x00F1` / `0x33F1`（`doip_client.py` 用 `u16()` 显式截断）。
> 这两个值本身不属于 DoIP 地址空间，列在这里只为证明"截断后同样 0x31"。

## 4. 网关自身 UDS：只有一个服务、两个 DID

### 4.1 服务集（1534 次请求，256 个 SID × 最多 6 种 payload 形状）

> 扫描前做了 socket drain + 校验负响应回显的 SID（防"上次超时的响应被这次读走"）。
> 未加这一步时 SID 0x12/0x13 出现过 `7F 12 11` 之类的串扰假象；隔离复测（新连接、6s 超时）
> 后两者均规整回 `7F 12 11` / `7F 13 11`。证据 `doip_sid12_13_isolate.txt`。
> 最终 1533/1534 条有响应，唯一无响应的是 SID 0x92 的某一个 payload 形状（孤例，不影响结论）。

### 4.2 DID 空间（承接 cgw 组的全扫 0x0000–0xFFFF，本组复核）

| DID | 响应 | 含义 |
|---|---|---|
| `F1 90` | `62 F1 90 4356…3836` | VIN |
| `F1 A0` | `62 F1 A0 07E0 07E8 07E1 07E9` | **4 个 CAN 诊断 ID**（见 §5） |
| 其余 65534 个 | `7F 22 31` | 不存在 |

cgw 组全扫里有 38 个 DID 当时"无响应"（0x3CE0-0x3CE2、0x8DA0-0x8DA9、0xA7E0-0xA7F7、
0xF1A8）。本组用 4.0s 超时 × 3 轮逐条复测：**全部稳定返回 `7F 22 31`**，
其中 0xA7EA / 0xA7F2 / 0xA7F3 各命中一次 4.0s 超时——即长尾延迟，不是代码路径差异。
证据 `doip_did_anomaly_retest.jsonl`。

### 4.3 `22` 的解析很粗糙（可利用信息：无）
只有**恰好一个 2 字节 DID**（UDS 段长度 3）才会被处理；其余形状一律 `7F 22 11`：

```
22                    -> 7F 22 11
22 F1                 -> 7F 22 11
22 F1 90 F1 A0        -> 7F 22 11   （不支持一次读多个 DID）
22 F1 90 AA BB        -> 7F 22 11   （不忽略尾部多余字节）
22 F1 90              -> 62 F1 90 …
```
所以"多 DID 一次读"、"带填充"这类组合把戏在这台上不成立。

## 5. `F1 A0` 的真实含义（对 cgw 组的移交）

```
07E0  07E8  07E1  07E9
```

这四个值落在 ISO 15765-4 的**动力总成诊断 ID 段**：
`0x7E0` = 第一组诊断请求，`0x7E8` = 对应响应，`0x7E1/0x7E9` = 第二组请求/响应。

把它当 DoIP 逻辑地址用（TA=0x07E0/0x07E8/0x07E1/0x07E9）全部得到 `7F 3E 31`
（网关本地拒绝，**没有转发到 CAN**，见 [HYP-doip-001](../02_HYPOTHESES/HYP-doip-001-f1a0-is-can-id-table.md)）。

**结论：`F1 A0` 是 13401 CAN FD 桥暴露的 CAN 诊断 ID 清单，不是 13400 的路由表。**
→ 13400 侧不存在通往这些 ECU 的路径；要打 0x7E0/0x7E8 必须走 13401。

## 6. 协议层偏离清单（合规性发现，非取数漏洞）

见 [HYP-doip-004](../02_HYPOTHESES/HYP-doip-004-routing-activation-not-bound-to-sa.md) 与
[HYP-doip-005](../02_HYPOTHESES/HYP-doip-005-length-and-version-abuse.md)：

1. **routing activation 不绑定 SA**：socket 激活一次后，任意 SA（含 0x0000、0x1000 网关自身、
   0x07E0）都能发诊断并被正常应答；同一 SA 还能在多个 socket 同时激活（规范要求 0x03）。
2. **未激活时用错协议层**：回 UDS `7F <sid> 22`（conditionsNotCorrect）而不是 DoIP `0x8003` NACK 0x02。
3. **激活类型不校验**：0x00–0x04、0xE0(OEM)、0xFF(保留) 全部 0x10 成功，OEM 数据被忽略。
   （规范要求不支持的类型回 0x06。）
4. **协议版本不匹配时静默丢弃**，不按规范回 NACK 0x00。
5. **识别响应多 1 字节**（33 vs 32）。`0x0002`（按 EID 识别）/ `0x0003`（按 VIN 识别）
   一律 NACK 0x01，而 `0x0001` 带 6 字节垃圾数据反被接受。
6. `0x0007` alive check、`0x4001` entity status、`0x4004` power mode 一律 NACK 0x01（未实现）。

**定级建议：中低危**——SA 不校验在多实体拓扑里会绕过"哪个 tester 能访问哪个 ECU"的准入设计，
但本靶场 13400 后面没有第二个实体，未观察到越权读取，报告里不要写成"可越权访问任意 ECU"。

## 7. 该面是否藏着 flag —— **没有**

对全部 13400 证据按赛事宽松正则 `[A-Za-z0-9_]{2,20}\{[ -~]{1,120}\}` 检索：
零命中。可读数据只有 VIN、4 个 CAN ID、EID/GID，都是结构性固定值，不是载荷。

**13400 的定位：一个"只读 VIN + 只读一张 CAN ID 表"的最小 DoIP 实现，作为到 13401 的路标，
本身不含 flag。** T03 的得分点应在 13401（CAN FD 桥）或 8080 上。
