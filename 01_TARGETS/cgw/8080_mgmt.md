# 8080 管理口 —— 协议层复核（CGW 侧）

采集者：cgw｜时间：2026-11-14 09:42–09:44 CST｜目标：10.229.221.2:8080（.4 同源，web 组已证三台指纹一致）

## 结论

8080 是 **Go net/http + Go 1.22+ ServeMux 的存活探针桩**，只注册了**精确路径** `/healthz`；
除 web 组已扫的 1576 条路径外，本轮把"协议层怪点"补齐，**没有发现任何新路由、新方法、新协议面**。
唯一与 .2 的差别是 .2 额外有 `/graphql`（TSP 的桩），不属于 CGW。

## 本轮新增的原始观测（`03_EVIDENCE/cgw/0513_8080_protocol_oddities.jsonl`）

| 请求 | 响应 | 判读 |
|---|---|---|
| `GET /healthz HTTP/1.1` + `Connection: close` | `200`，`Content-Type: application/json`，`Content-Length: 16`，body `{"status":"ok"}\n` | 无 `Server` 头（Go 默认） |
| `GET /healthz HTTP/1.0`（无 Host） | `200 HTTP/1.0`，同 body | 兼容 1.0 |
| `OPTIONS * HTTP/1.1` | `200`，`Content-Length: 0` | Go server 对 `*` 的默认处理，不是自定义路由 |
| `CONNECT 10.230.164.2:8080` | `404 page not found` | 非代理 |
| 绝对 URI `GET http://10.229.221.2:8080/healthz` | `200` | 按 path 路由（Go 行为） |
| `POST /healthz` + `Transfer-Encoding: chunked` | `200` | 任意方法+任意 body 都 200 |
| `POST /healthz` + CL:4 + TE:chunked（走私探针） | `200` | Go 忽略 CL 用 TE，无后端可走私 |
| 重复 `Host:` 头 | **400 Bad Request** | Go 对 duplicate Host 的拒绝，非漏洞 |
| `GET /healthz?debug=1&internal=1` | `200` | query 被忽略（与 TSP 桩同风格） |
| `GET /x/../healthz` | `307` → `Location: /healthz` | ServeMux cleanPath |
| `GET /healthz%00` | `404` | 按转义路径路由，不先解码 |
| `Upgrade: websocket` | `200` 普通 JSON，无 101 | 无 WebSocket |
| `GET /` + 8000×`a` | `404` | 未触发 414（Go 默认 header 上限 1 MB 内） |
| `POST /healthz` + JSON body | `200` | 无 body 解析 |

## 未发现（明确记录，避免重复投入）

- 没有 `Server`/`X-Powered-By`/CORS/Set-Cookie；没有 vhost 路由（web 组 12 种 Host 已试）。
- 没有 h2c/gRPC（web 组已试 `PRI *` → 400 + `Connection: close`）。
- 没有 OPTIONS 预检、没有 PUT/DELETE/TRACE 差异（web 组方法矩阵已覆盖）。
- 没有"管理 API 需要特殊 UA/Authorization 才从 404 变 200"的迹象：`/healthz` 对任意方法都 200，
  其余路径恒 404，说明路由表就是硬编码两条（.2 三条）。

## 对 13401 的意义

lead 提过"8080 侧是否有 CANGW 转发 API"——本结论为**否**：8080 的 handler 不接受任何参数
（query/body/method 都被忽略），不存在"转发到内部 CAN 侧"的入口。13401 的空监听不能从 8080 侧绕过。
